# adblock-jni

Thin JNI wrapper around Brave's [adblock-rust](https://crates.io/crates/adblock) for the Prosto
browser. Kotlin side: `com.jestk.browser.engine.adblock.AdblockNative` (contract in the content
blocking plan). The prebuilt `.so` files are committed under `app/src/main/jniLibs/`, so Gradle
builds need no Rust.

## Layout

- `src/core.rs`: pure logic (engine build, request check, cosmetic JSON, scriptlet parsing, type
  code mapping). Tested on the host.
- `src/glue.rs`: the `Java_com_jestk_browser_engine_adblock_AdblockNative_*` exports. Every call
  returns its safe value (0, null, `{}`) on bad input or panic and never throws.
- `tests/engine.rs`: `cargo test` suite. It loads `tools/filterlists/scriptlet_stubs.json`, so the
  contract with `tools/build_scriptlets.mjs` is pinned by a test.

## Pinned versions

`adblock =0.13.5` (features `embedded-domain-resolver`, `full-regex-handling`, `css-validation`; default features off,
which drops `single-thread`), `jni =0.21.1`, Rust stable, NDK r28 (`28.2.13676358`), platform 26.
`nativeVersion()` returns `2-adblock-0.13.5`; the serialized engine format is only valid for the same
crate version, so cache file names must carry it.

## Rebuild

```
tools/build_native.sh
```

Checks the toolchain, runs `cargo test`, builds `arm64-v8a`, `armeabi-v7a` and `x86_64` with
`cargo ndk`, links with `-z max-page-size=16384`, and fails unless every `LOAD` segment has
alignment >= 0x4000 (`llvm-readelf -l`). Prerequisites: rustup with the three Android targets,
`cargo-ndk`, an Android NDK under `$ANDROID_HOME/ndk`.

## Thread safety

With default features off, `Engine` is `Send + Sync`; `core.rs` asserts it at compile time
(`assert_send_sync::<Engine>()`). But adblock-rust holds one `std::sync::Mutex` (its regex manager)
for a whole network check, so concurrent checks run one at a time anyway. On a Motorola Edge 60
Fusion, four threads hammering one engine took a 27 us check to p50 2.3 ms / p99 8.7 ms: a contended
futex parks and wakes threads far slower than the check itself. Each handle therefore holds a
`core::Guarded` engine, a spin-then-yield lock in front of the engine; with it the same run is
p50 88 us / p99 377 us, close to plain queueing (pinned by `guarded_engine_serves_concurrent_callers_correctly`).
Rules for the Kotlin caller:

- `checkRequest`, `checkRequestRedirect`, `urlCosmeticResources`, `hiddenClassIdSelectors` and
  `serialize` may be called from any thread; they serialise on the handle's guard.
- `useResources` takes `&mut Engine`: call it right after create/deserialize, before the handle is
  shared. `destroy` must not race with any other call (Kotlin holds a write lock).

## `checkRequest` flags

`1` BLOCK, `2` IMPORTANT, `4` EXCEPTION, `8` REDIRECT, `16` MATCHED (a block filter matched, even if
excepted). `0` = allow, also for every error (empty or unparseable URL, unknown type code).

## Resources JSON (`useResources`)

A JSON array of adblock-rust `Resource` objects, or an object with a `resources` array (extra keys
such as `_format` are ignored). Resources replace the previous set and are not serialized with the
engine: call it again after every `createFromSerialized`.

- Redirect resources: `{"name":"googletagmanager_gtm.js","aliases":[...],"kind":{"mime":"application/javascript"},"content":"<base64>"}`.
- Scriptlet stubs (format finally used; generated by `tools/build_scriptlets.mjs` into
  `tools/filterlists/scriptlet_stubs.json`):
  `{"name":"json-prune.js","aliases":[...],"kind":"template","content":"<base64>"}` where the
  decoded content is the single-line JSON array `["json-prune","{{1}}","{{2}}",...,"{{10}}"]`.
  adblock-rust fills `{{n}}` with the JSON-escaped arguments of `##+js(name, a1, a2)` and emits
  `try {\n<array>\n} catch ( e ) { }\n` per scriptlet. `urlCosmeticResources` parses each array
  line back into `[name, arg1, ...]` and drops trailing unfilled `{{n}}` slots, so no JS is ever
  returned. Up to 10 arguments. Aliases (`aopr`, `acs`, ...) resolve to the canonical name stored
  in the stub body, which is the key into the `scriptlets.js` bundle.

## `urlCosmeticResources` JSON

`{"hide":[..],"exceptions":[..],"procedural":[..],"generichide":false,"scriptlets":[["json-prune","a","b"]]}`;
on error `{}`. Sets are sorted for stable output.

`procedural` holds one JSON-encoded adblock-rust `ProceduralOrActionFilter` string per rule:
`{"selector":[{"type":"css-selector","arg":".a"},{"type":"has-text","arg":"/foo/i"}],"action":{"type":"remove"}}`.
`selector` is a list of operators (`css-selector`, `has-text`, `upward`, `xpath`, `matches-css`,
`matches-css-before`, `matches-css-after`, `matches-attr`, `matches-path`, `min-text-length`; each
`arg` is a string); `action` is absent (hide) or one of `remove`, `style`, `remove-attr`,
`remove-class` (`arg` is a string except for `remove`). The `css-validation` crate feature is
required: without it adblock-rust keeps `.a:has-text(x)` as one opaque CSS selector and puts it
into `hide`, where it invalidates the whole stylesheet rule it is grouped into (pinned by
`procedural_operators_are_split_out_of_the_hide_list`).

## `$popup`

adblock-rust has no popup request type, so `||host^$popup` never matches a `document` request
(pinned by `popup_option_does_not_block_document_requests`). The Kotlin side compiles the lists'
`$popup` rules into a third, small "popup" engine, rewritten to `$document` (`PopupRules`), and
checks a popup's target there as a `document` request with the opener as source; this covers
path rules, `domain=`, exceptions and downloaded lists (pinned by
`rewritten_popup_rules_block_the_fixture_popup_targets`). The build-time `$popup` host list is only
the fallback before the engines are ready.

## Sizes (stripped, LTO, `opt-level = 3`, 16 KB aligned)

| ABI | bytes |
| --- | --- |
| arm64-v8a | 3,260,256 |
| armeabi-v7a | 2,216,376 |
| x86_64 | 3,443,016 |

`opt-level = 3` over `"z"`: on the phone a check takes p50 14 us vs 28 us (p99 20 vs 40 us), which
halves the time each check holds the guard, for about 17% more library size (arm64 2.79 MB with `z`).
