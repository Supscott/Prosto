# Platform Guidelines

Detailed platform-specific posting conventions and mechanics for sharing developer project updates and feature previews.

---

## 1. Reddit

### Primary Purpose
In-depth community discussion, workflow feedback, and peer critique from developers and tech enthusiasts (e.g. `r/androiddev`, `r/browsers`, `r/SideProject`, `r/webdev`).

### Format & Structure
- **Title (Crucial):**
  - Keep under 120 characters for clean mobile wrapping.
  - Formula: `[Concrete Problem / Annoyance] + [Direct Solution / What was built]`
  - Example: *"I wanted a faster way to switch between search engines on mobile, so I built one"*
  - Never use clickbait, hyperbolic claims ("The best browser ever"), or vague teasers ("You won't believe what I made").
- **Body:**
  - Clear paragraph breaks (Reddit markdown collapses single line breaks; use double line breaks).
  - Structure:
    1. Context / Relatable itch (1–2 sentences).
    2. Friction in current standard tools (1–2 sentences).
    3. The specific interaction / solution implemented.
    4. Optional notes on customizability or scope.
    5. Neutral, specific discussion prompt asking about users' existing habits or workflows.
- **Media:**
  - Direct video uploads (`.mp4`) perform drastically better than external YouTube or blog links.
  - Keep clip under 30–45 seconds focusing on one fluid interaction.

---

## 2. X / Twitter

### Primary Purpose
Fast, punchy demonstration of a visual interaction or micro-feature with high shareability in developer circles.

### Format & Structure
- **Hook (Sentence 1):**
  - Must deliver the entire premise in under 100 characters.
  - Readers watch the attached video while scanning line 1.
- **Length & Layout:**
  - Standard post limit is 280 characters.
  - Use 2–3 short lines separated by whitespace.
  - No bloated backstory or preamble.
- **Tone & Hashtags:**
  - Conversational dev log style.
  - Avoid hashtag spam (max 0–1 relevant tags like `#AndroidDev` or `#JetpackCompose` if appropriate, but prefer none).
- **Threads (if extending):**
  - Post 1: Self-contained problem + video demo.
  - Post 2: Technical detail or customizability note (e.g., custom search provider syntax, gesture mechanics).

---

## 3. Threads

### Primary Purpose
Conversational dev log, personal perspective on building software, and engaging with mobile/tech audiences.

### Format & Structure
- **Length & Layout:**
  - 500 character limit.
  - Feels slightly more personal and reflective than Twitter, but less formal than Reddit.
- **Pacing:**
  - State the annoyance or workflow challenge first.
  - Explain the prototype or feature tested.
  - Close with an invitation for suggestions or workflow habits.
- **Avoid:**
  - Aggressive growth-hacking tropes ("Comment 'LINK' below", "Follow for more").
